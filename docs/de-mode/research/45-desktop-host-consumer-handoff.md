## Host authority and startup

Electron resolves `AI_TOOLKIT_USER_DATA` before importing storage consumers;
the override must be absolute. Without it, userData is
`app.getPath('appData')/AI Toolkit`, matching the confirmed native default.
Rust alone initializes/detects/migrates profiles and owns context/file authority.
The old global `ucpInstallation` fallback is removed from live service dispatch.

Private main code authenticates the actual `event.sender` and its main frame.
Host window IDs are injected there and never accepted through preload. A local
IPC registration facade centrally gates every retained Classic channel,
including configuration, skins, file/library/media/game operations and legacy
events. DE cannot enter those handlers even if it loads a Classic URL. A
Classic call captures its bound context at ingress using AsyncLocalStorage;
root arguments must match that context and late publication checks its logical
owner. Standalone map listing stays empty; map/native-tile calls require a bound
root, preventing the old implicit installed-game fallback.

`deDesktop` exposes only context, chooseInstallation, openRaw, pickSavePath,
saveRaw, reconcile, recoverOriginal, confirm, close and an owned onClose listener.
It exposes no generic request, initialize, whole-store CAS, host owner, bind,
prepare or commit command. Native frontend `de-api.ts` sends the same generated
raw DTOs to the parent's narrow commands and does not import Classic codecs.

Every fresh Electron window loads the static, script-free
`desktop-pending.html`. It binds an inherited/startup context before activation
or routing. Folder selection prepares and commits only in that new no-document
window; cancellation/refusal leaves the original context/session intact. A lost
commit reply gets one activationStatus query, never a commit replay or automatic
reconnect. Only after binding/commit and pending-page completion does the host
load desktop-start. That page routes persisted Classic to index, DE to de, and
shows explicit folder/DE-standalone/Classic-standalone choices for standalone.
Main startup preserves restoreProject=1; inherited/fresh windows use0.

Classic runtime directory preparation now occurs only after the final bound
edition is Classic, before its route. DE/standalone never prepare Classic skins/
config just by starting. The final actual-main VM regression exercises this
boundary. Electron retains the existing Windows native overlay caption; the DE
route reserves its title strip and supplies a drag region without loading the
Classic shell. The parent's native implementation uses its own conventional DE
decorations and separately gated Classic migration.

## Documents, drafts and save recovery

There is exactly one accepted DS1 session over D1. Raw results have the explicit
`rawBytes` discriminant. Base64 is decoded into bytes directly; no
`documents.ts.decodeDocument`, Classic character normalizer or projection-based
JSON serialization enters this path. Existing/unknown/duplicate fields, BOM,
trivia and large numeric tokens remain with the same document owner.

The controller owns Open/Save/Save As, dialog cancellation, unsaved close/open
gates, explicit adoption, intermediate refresh and recovery presentation. Open
constructs/parses the candidate before adoption and rechecks context generation,
session, content revision and the opaque draft token after asynchronous work.
An authorized draft discard takes effect only on successful unchanged adoption;
cancelled/invalid/foreign/stale results retain the original draft and session.
Typing while a confirmation/picker is open invalidates that authorization.
The panel adds only an integer view-change token on input/reset, not a second
draft validator or document model.

Save As cancellation occurs before DS1 creates a snapshot. A real save reserves
DS1's one slot before platform SHA-256, carries its exact seven fields and
serialized bytes, and acknowledges only a matching receipt. An older committed
snapshot does not replace later content or history. Save completion settles the
captured session and refreshes only its current mount; late callbacks after
disposal cannot adopt or refresh a replacement session. Authorized close bypasses
the beforeunload preservation guard only after its unsaved gate.

Operation IDs derive from generated `saveOperationPrefix`:
`save1/<ownerId>/<documentId>/<saveId>`. Core rejects differing metadata reuse
and owns the durable ledger. Rejected/missing/mismatched replies retain the exact
snapshot as unknown, including duplicate-ID rejection; they never authorize
another save. Only matching backend committed/failed/cancelled outcomes release
the slot as DS1 specifies. Reconciliation queries that same ID and never writes.

C1 admission still lives in CoreClient. The generic request synchronously reserves
and serializes before hello/await; requestBytes' byte path is unchanged. Generated
`writeOperations` (including context subcommands) and `resultKinds` replace manual
transport inventories. Submitted lost writes become unknown; queued cancellation
is a known cancellation. The private host adapter correlates all seven metadata
fields for those noncommit/unknown transport receipts and never manufactures a
committed receipt.

Recovery is explicit. Main retains the last authenticated context, starts a new
client only when the prior client failed, initializes it and privately restores
the original context; an already healthy owner is read with current. It never
binds startup, chooses the new default or replays a write. The logical owner and
DS1 remain; only transportEpoch changes. Other windows restore only through their
own explicit action. Tauri's frontend recovery reads current because its core
remains in-process.

An operation killed before a durable ledger record can remain unknown after
recovery. The controller retains that snapshot and blocks replacement/another
save rather than inferring success from target bytes. This is an honest residual
outcome, not durable session recovery or a completed abandoned-operation UX.
