## Frozen contract and ownership

Root approved the canonical extension before coupled edits. Immutable
`interface-r4.txt` and labeled native-readiness, Windows-frame correction and
outcome amendments retain the decision and its corrected premises. Nothing was
silently rewritten. Rust alone defines/exports `InstallationSelection`:

```text
cancelled
opened  {selectedPath, profile}
failed  {selectedPath, profile|null, code, diagnostics}
unknown {selectedPath, profile|null, code, diagnostics}
```

Cancellation preserves the parent's prior displayed choice. Opened requires
the target completion/commit path. Failed means a known precommit failure or
canonical refusal. Unknown means an already submitted commit whose reply and
one exact status query cannot establish an outcome, including a deadline during
submission. The remembered default may have changed. Unknown never fabricates
opened, unchanged-default proof, replay or a compensating profile writer; its
owned unused child is destroyed and its owner closed when reachable.

One host-only `stageActivation {activationId,ownerId}` extends the existing Rust
activation owner. Preparation detects the installation. Stage carries that
prepared profile/fingerprint into a fresh destination context without writing
the profile repository. Current/startup/assets may read it; raw document
acquisition, adoption, save, further activation and tentative recovery are
refused. Legacy mutation ingress is also gated. The final commit reprobes and
persists through the existing repository, retaining the staged logical identity.
Existing prepare→commit-only callers/semantics remain supported. Successful
children become independent of their former parent. Close/failure retires the
stage, child context and owned native label registrations.

The host sequence is bind fresh child → prepare → stage → load the exact local
DE/Classic route → require matching route Finished plus bootstrap-ready →
recheck parent/child/context → show → recheck → commit. The 15-second opening
budget covers pending route/readiness and counts native construction/show time;
a late constructor completion cannot reset it and publish defaults. Synchronous
OS calls themselves are not forcibly preempted. The folder picker is outside
that budget. Parent/child closure and timeout cancel the unused opening. No
document is admitted into it, and no second unsaved/session protocol exists.

Electron authenticates the sender/main frame, actual target URL and logical
owner. Native correlates its actual injected WebviewWindow, pending activation,
owner, expected bundled route/query and parent/context liveness. It suppresses
the previous early `de_request`/Classic Ready show paths while opening. Native
failed build/load/show/commit paths close the owned context and destroy only the
unused child. Native parent destruction cancels pending owned children; the
core also checks the inherited parent's identity at activation under its lock.

The bootstrap-ready bridge grants no installation authority. On Windows the
injected listener explicitly returns for `window !== window.top` before
capturing its private host arguments. Tauri's general main-frame-only API text
has an explicit Windows subframe exception; the earlier incomplete claim is
retained in evidence and corrected by the labeled amendment. Same-origin code
with access to the parent DOM can trigger its events; this is correlation, not
an anti-tampering boundary. Wry Finished uses WebView2 NavigationCompleted and
does not itself check success. The matching bootstrap signal is separately
required; neither signal proves arbitrary editor features or game behavior.

Protocol is now1.4 for the added host command. Document1.3 adoption, receipts,
unknown-save and Close semantics are retained. Types/metadata were produced by
